DataViewer Enterprise - v2.7.0 - 2026-07-01

New Features
- Responsive interface overhaul: the application now works at any window size or aspect ratio, down to a 480x360 floor.
  Split-screen, corner-snap, and unusual monitor shapes no longer clip or hide any part of the UI.
- Every major region (data view, navigator, notes, ribbon, dialogs) scrolls when space runs out instead of cutting content off.
- Smarter ribbon: buttons keep their labels for as long as they genuinely fit the window width and only then switch to compact icons.
  Vertical spacing around the ribbon buttons is a tight, consistent 5 pixels in both modes.
  The compact/labeled state is now uniform across all four tabs (Home, Reports, Tools, Settings): switching tabs never changes the toolbar's appearance, since the widest tab decides for all of them.
- At very narrow widths the navigator collapses to a slim icon strip (never disappearing), and a status-bar "Notes" button keeps the notes panel reachable.
- Improved pop-out panels: the Navigator and Notes panels now float with the same comfortable default size, can be freely resized while floating, and can be dragged or double-clicked back into place at any window size.
- Panels always start a session attached to the window. A panel left floating when the app closed used to come back floating in a state that could not be dragged back in; now it simply returns to its docked position on the next launch.
- Long names in the Navigator are always fully reachable: the Navigator keeps itself wide enough that none of its content can hide beyond the panel edge, the file/sheet tree scrolls horizontally all the way to the end of the name, session lists scroll smoothly per pixel, long values in Sample Properties wrap onto extra lines, and hovering any entry shows the complete name in a tooltip.
- Loading a data file no longer disturbs an Excel you already have open: the reader now uses its own private, invisible Excel instance instead of borrowing (and then closing) yours.
- Windows text-scaling (125% / 150% / 200%) is respected: buttons and rows grow with the font instead of clipping labels.
- New TPM button on the Home ribbon next to Sensory and Detailed Sensory, so all three modes switch with a single click and the active mode stays highlighted.
- Pick a default startup mode: the first launch after this update asks which mode DataViewer should open in (TPM, Sensory, or Detailed Sensory), and the app then opens in that mode every time. Change it whenever you like via Settings > Set Default Mode.
- New Save button in TPM mode (next to New File): saves a copy of the currently loaded file under a name you choose, including every edit made in the app.
- Ribbon buttons no longer shift position when switching modes: New/Save/Load/Close sit in the same spots in TPM, Sensory, and Detailed Sensory.
- Startup popups now appear one at a time: the default-mode question comes first, and the "pick up where you left off" recovery offer waits until it is answered.
- Report Draw Pressure charts now use the real puff range on the x-axis (previously stuck at 0 to 1). The same fix applies to the in-app Draw Pressure plot.
- Every chart with an x and y axis now follows one consistent rule: the x-axis runs from puff 0 to the last measured puff plus 1, and the y-axis is anchored at 0 and tops out at the highest value plus 1. No more per-chart floors or clipped peaks, and no data point is ever cut off at an axis edge.
- The report table's Draw Pressure column now shows the true average of the measured values (it was previously the median).
- Draw pressure is correctly labeled in kPa everywhere (the chart axis previously said Pa), and the report table column carries the unit.
- New sensory sessions now start with "Blind?" set to Yes (most tests are blind); previously saved sessions keep whatever was recorded.
- Viscosity is no longer reported as 0 when the template cell contains units (for example "800kcp"): the number is read out of the text, and a k multiplier is applied (800kcp reads as 800,000 cP). The same tolerance applies to all numeric header fields.

Quality
- A new automated screenshot harness renders the app across 28 window-size and text-scale combinations on every build and verifies nothing clips without a scrollbar.
- A full-sprint audit repaired every sizing regression it found; the complete test suite (51 suites, including live-database end-to-end checks) is green.
