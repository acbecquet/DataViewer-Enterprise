==============================================================================
  1. APPLICATION OVERVIEW
==============================================================================

  DataViewer Enterprise is a C++ Qt6 desktop application for analyzing TPM
  (Total Particulate Matter) test data and sensory evaluation data. It reads
  Excel workbooks containing standardized test templates, displays measurement
  data in editable tables and plots, and generates branded PowerPoint reports.

  The application operates in two distinct modes:

    - TPM Mode (default): Load Excel test files, view per-sample measurement
      data (puffs, weights, draw pressure, resistance, TPM calculations),
      navigate between samples and sheets, edit data inline with automatic
      recalculation, generate PPTX reports with data tables and plots.

    - Sensory Mode: Create and manage sensory evaluation sessions with
      sample cards scored on five metrics (Burnt Taste, Vapor Volume,
      Overall Flavor, Smoothness, Overall Liking) on a 1-9 scale, visualize
      results on a radar chart, generate single or combined PPTX reports,
      import data from standardized Excel templates or JSON files.

  Target executable: DataViewer.exe
  Installer: DataViewer-setup.exe (version-independent name for permissions)
  Namespace: DVE
  Build system: qmake (.pro file) + MinGW 13.1.0
  Qt version: 6.10.1
  Minimum window size: 1280x800, default 1600x900
  Supports drag-and-drop file loading


==============================================================================
  2. ARCHITECTURE
==============================================================================

  --------------------------------------------------------------------------
  2.1  Mode Switching
  --------------------------------------------------------------------------

    The Tools ribbon tab contains a checkable "Sensory" toggle button. When
    toggled, the MainWindow transforms in place via two QStackedWidgets:

      m_centralStack (central area):
        Index 0 = TPM view (QSplitter with data table + PlotWidget)
        Index 1 = SensoryPanel (sample cards + RadarChartWidget)

      m_navStack (left dock navigator):
        Index 0 = QTreeWidget file browser (TPM files and sheets)
        Index 1 = QListWidget session list (sensory sessions, multi-select)

    The SensoryPanel is created lazily on first activation via
    initSensoryPanel(). The ribbon buttons swap visibility and connections
    via updateRibbonForMode():

      - Home tab: TPM buttons (New File, Load File, Close) are hidden and
        replaced by sensory buttons (New Session, Save, Load Files, Load
        Database, Close).

      - Reports tab: "Test Report" becomes "Single Sensory Report" and
        "Full Report" becomes "Full Sensory Report". Report buttons use
        the ccell icon in sensory mode. The Data Cleanup group is hidden
        in sensory mode.

  --------------------------------------------------------------------------
  2.2  Ribbon
  --------------------------------------------------------------------------

    The ribbon (RibbonWidget) has three tabs:

      Home:
        - File group: New File, Load File, Close (TPM)
        - File group: New Session, Save, Load Files, Load Database, Close
          (Sensory -- shown/hidden based on mode)

      Reports:
        - Generate group: Test Report / Single Sensory Report,
          Full Report / Full Sensory Report
        - Data Cleanup group: Clean Data, Reset Cleanup (TPM only)

      Tools:
        - Utilities group: Sensory toggle (ccell icon), Database browser
        - Images group: Image Inbox button

    Button labels use word-wrap (setWordWrap(true)) with 80x76px fixed
    size to prevent text truncation on multi-word labels.

  --------------------------------------------------------------------------
  2.3  Dock Panels
  --------------------------------------------------------------------------

    A single left dock ("Navigator") contains a vertical QSplitter with
    three sections:

      Top (~35%): File/session navigator
        - In TPM mode: QTreeWidget showing loaded files as parent nodes
          with sheet names as children. Clicking a sheet navigates to it.
        - In Sensory mode: QListWidget with ExtendedSelection (Ctrl+Click,
          Shift+Click). Single selection switches session and restores
          normal card view. Multi-selection triggers an averaged radar
          chart across selected sessions. Empty selection clears the chart.
          Deselecting updates the chart in real time.

      Middle (~13%): Test Averages panel (Sensory mode only)
        - QListWidget showing unique test titles across loaded sessions
        - Clicking a test title computes device-grouped averages across
          all sessions sharing that title and displays results as:
          (a) an averaged radar chart, and (b) a table overlay in the
          left panel replacing the sample cards
        - Re-clicking the same item re-displays the averaged table
        - Uses itemClicked signal (not currentRowChanged) to ensure
          re-click works after navigator deselection

      Bottom (~52%): Sample Properties
        - QTableWidget with Property/Value columns, inline-editable
        - Load Images / View Images buttons below the property table
        - Works for both TPM samples and sensory sessions

  --------------------------------------------------------------------------
  2.4  Status Bar
  --------------------------------------------------------------------------

    - Status message label (left)
    - Database sync indicator (permanent, right)
    - Progress bar (permanent, shown during long operations)
    - File info label (permanent, right)

  --------------------------------------------------------------------------
  2.5  Central Area (TPM Mode)
  --------------------------------------------------------------------------

    A vertical QSplitter (50/50 default):

      Top: Data table panel
        - Sample navigation bar: Previous/Next buttons (Ctrl+Left/Right),
          sample counter, Add Row / Remove Row buttons
        - QTableWidget with 12 columns: Puffs, Before Weight, After Weight,
          Draw Pressure, Resistance, Smell, Clog, Notes, TPM, TPM Power
          Density, Variation, Oil Consumed
        - Columns 0-7 are editable; columns 8-11 are calculated and
          read-only
        - Cell edits trigger recalculation of TPM metrics and debounced
          write-back to the source Excel file

      Bottom: PlotWidget
        - Renders plots for the current sheet data
        - View tab allows toggling Table Only, Plots Only, or Both

  --------------------------------------------------------------------------
  2.6  Central Area (Sensory Mode)
  --------------------------------------------------------------------------

    SensoryPanel fills the central area. Layout from top to bottom:

      Header row: Test Title, Assessor, Tester, Media (QLineEdits) + Date
        label (auto-populated with current date)

      Horizontal QSplitter (50/50):
        Left: QStackedWidget with two pages:
          Index 0: Scrollable FlowLayout of SampleCards + "Add Sample" button
          Index 1: Averaged table overlay (QTableWidget, read-only) shown
            when test averages are selected. Device column is 1.5x wider
            than metric columns. Headers styled with #1F4E79 background.
        Right: RadarChartWidget

  --------------------------------------------------------------------------
  2.7  Keyboard Shortcuts
  --------------------------------------------------------------------------

    Ctrl+O        Open/Load file
    Ctrl+S        Save (routes to sensory save in sensory mode)
    Ctrl+U        Update database with modified files (TPM + sensory)
    Ctrl+Left     Previous sample
    Ctrl+Right    Next sample


==============================================================================
  3. SENSORY MODE FEATURES
==============================================================================

  --------------------------------------------------------------------------
  3.1  SensoryPanel Layout
  --------------------------------------------------------------------------

    The SensoryPanel (src/ui/SensoryPanel.h/.cpp) fills the central area
    when sensory mode is active. See Section 2.6 for layout details.

  --------------------------------------------------------------------------
  3.2  Sample Cards
  --------------------------------------------------------------------------

    SampleCard is a QGroupBox (fixed 175x340 px) containing:
      - Name field (QLineEdit with placeholder "Sample N")
      - Five metric QSpinBoxes (range 1-9, default 5) in DATA-ENTRY order:
          Burnt Taste, Vapor Volume, Overall Flavor, Smoothness,
          Overall Liking
        (This matches the physical evaluation sheet layout)
      - Comments field (QTextEdit, 40-60px height)
      - Remove button (bottom-right corner)

    Cards are arranged in a FlowLayout that wraps left-to-right then down,
    centered within each row. Any change to a card's fields triggers a
    debounced (150ms) radar chart refresh.

  --------------------------------------------------------------------------
  3.3  Radar Chart
  --------------------------------------------------------------------------

    RadarChartWidget (src/ui/RadarChartWidget.h/.cpp) is a custom-painted
    QWidget that draws:
      - Concentric grid circles (1-9 scale)
      - Five axis lines with metric labels in PLOT order:
          Overall Liking (12 o'clock), Burnt Taste, Vapor Volume,
          Overall Flavor, Smoothness (clockwise)
      - Filled polygons for each sample, color-coded
      - Clickable legend that toggles individual sample visibility
        (m_hiddenSamples set)

    The chart accepts a QVector<SensorySession> and draws all samples from
    all sessions. It uses a static color palette (kColors).

    Two separate metric orderings are defined in SensoryData.h:
      kSensoryMetrics     — data-entry/table order (Burnt Taste first)
      kSensoryMetricsPlot — plot order (Overall Liking at 12 o'clock)

  --------------------------------------------------------------------------
  3.4  Session Management
  --------------------------------------------------------------------------

    Sessions are stored as QVector<SensorySession> within SensoryPanel.
    The m_currentTesterIdx tracks which session is displayed.

    Operations (called by MainWindow via ribbon buttons):

      newSession():
        - Saves current session state
        - Appends a new empty session with current date
        - Clears all cards, adds one default card
        - Emits sessionsChanged() to refresh navigator

      selectSession(int index):
        - Saves current session, switches to the specified index
        - Applies the session data to the UI (header fields + cards)

      closeSessions(QVector<int> indices):
        - Removes sessions at the given indices (sorted descending to
          avoid index shifting)
        - If all sessions are removed, leaves empty panels (no auto-create)
        - Otherwise clamps current index and applies the nearest session

      loadSessions(QVector<SensorySession>):
        - Appends incoming sessions (skipping those with no samples)
        - If the panel is in default state (one empty card, all fields
          blank), replaces it
        - Applies the last loaded session

      showAveragedChart(QVector<int> sessionIndices):
        - Computes per-device averaged scores across the selected sessions
        - Builds a synthetic "Averaged" session and displays it on the chart
        - Triggered when multiple sessions are Ctrl+Click selected in
          the navigator, or when a test average is selected
        - Also triggered on deselection for real-time chart updates

      showAveragedTable(deviceNames, deviceAvgs):
        - Populates the averaged table overlay (QStackedWidget index 1)
        - Device column is 1.5x wider than metric columns
        - Replaces sample cards view

      showNormalView():
        - Restores sample cards view (QStackedWidget index 0)

  --------------------------------------------------------------------------
  3.5  Saving
  --------------------------------------------------------------------------

    save() writes to three destinations simultaneously:
      1. JSON file (.json) with session metadata and sample scores
      2. Excel file (.xlsx) via QXlsx with headers, score matrix, and
         session metadata below the data
      3. SQLite database via DatabaseManager::saveSensorySession()

    The save path is remembered (m_savePath) so Ctrl+S reuses it without
    prompting. First save prompts for a file location.

    If the current session label differs from the saved filename, a Save As
    dialog is automatically shown.

    If the test title is blank, the user is offered to reuse the previous
    session's test title or accept an auto-generated default from
    DatabaseManager::nextDefaultTestName().

    buildSession() preserves the existing sessionName when updating a
    session (doesn't regenerate the name), which is critical for database
    upsert matching.

  --------------------------------------------------------------------------
  3.6  Loading
  --------------------------------------------------------------------------

    loadFiles() (renamed from loadExcel()):
      - Opens one or more files (.xlsx or .json)
      - Routes by file extension:

      JSON files:
        - Parses the same format that saveToJson() writes
        - Extracts session metadata + samples array
        - Full round-trip fidelity with the save format

      Excel files — auto-detects format by inspecting cell A1:
        - If A1 == "Sample" → saved format (loadExcelSavedFormat):
          Flat table with "Sample | Metrics | Comments" header,
          one tester's devices as rows, metadata section below
        - Otherwise → standardized template (loadExcelStandardFormat):
          Multi-tester blocks organized by device, tester names in
          column A, multiple device blocks separated by blank rows,
          stops at "average" row

    loadFromDatabase():
      - Shows a picker dialog that lists all sensory sessions from the
        database, grouped by test title
      - Tree view with columns: Test Title/Tester, Assessor, Media,
        Date, Samples
      - Supports ExtendedSelection (multi-select)
      - Selecting a parent node selects all its children
      - Loads selected sessions via DatabaseManager::loadSensorySession()


==============================================================================
  4. IMAGE SYSTEM
==============================================================================

  --------------------------------------------------------------------------
  4.1  Loading Images
  --------------------------------------------------------------------------

    onLoadImages() in MainWindow handles both modes:

      TPM mode: Opens a file dialog for PNG/JPG/BMP files, stores paths
        in the current SampleResult's imagePaths list.

      Sensory mode: Opens a file dialog, stores paths in the current
        SensorySession's imagePaths list.

    The Image Inbox (ImageInboxDialog, accessed via Tools > Images) provides
    a dedicated workflow for assigning photos to TPM samples. In sensory
    mode, the inbox button simply redirects to onLoadImages().

  --------------------------------------------------------------------------
  4.2  ImageViewDialog (Crop and Resize)
  --------------------------------------------------------------------------

    ImageViewDialog (src/ui/ImageViewDialog.h/.cpp) provides a canvas-based
    image layout editor:

      Canvas: 800x450 pixels, proportional to a slide (13.333" x 7.5"
        at 60 px/inch)

      ResizableImageItem (QGraphicsObject):
        - Drag to reposition
        - Bottom-right corner handle for aspect-ratio-locked resizing
        - Crop mode with four corner handles (TL, TR, BR, BL) that adjust
          a normalized [0,1] crop rectangle
        - setCropRect() applies a previously saved crop on load
        - commitCrop() finalizes the crop, resizes the item, and updates
          the cumulative effective crop (m_effectiveCrop)

      Dialog controls:
        - Remove: delete selected image
        - Crop: toggle crop mode for the selected image
        - Reset: restore images to default positions
        - Hint label showing usage instructions

      The dialog returns:
        - imagePaths(): ordered list of remaining image file paths
        - imageLayouts(): QVector<QRectF> positions in inches
        - imageCrops(): QVector<QRectF> normalized [0,1] crop rectangles

      These are stored back into SampleResult (TPM) or SensorySession
      (sensory) and reproduced exactly in the generated report slides.

  --------------------------------------------------------------------------
  4.3  Database BLOB Storage
  --------------------------------------------------------------------------

    Images are stored as BLOBs in two tables:

      images table (TPM):
        - FK to samples(id)
        - image_data BLOB containing the raw file bytes
        - Layout fields: layout_x, layout_y, layout_w, layout_h (inches)
        - Crop fields: crop_x, crop_y, crop_w, crop_h (normalized 0-1)

      sensory_images table (Sensory):
        - FK to sensory_sessions(id)
        - Same schema as images table

    When saving to the database, images are read from disk and stored as
    BLOBs. When loading from the database, they are extracted and written
    to temporary files for display.

    Image persistence fix: Ctrl+U (database update) now saves both TPM
    files AND sensory sessions, ensuring images survive reload.

  --------------------------------------------------------------------------
  4.4  Image Processing for Reports
  --------------------------------------------------------------------------

    loadAndCropImage() helper (in SensoryPanel.cpp):
      - Reads the image file from disk
      - Applies the normalized crop rectangle if non-trivial
      - Downscales to max 1920px on either dimension if needed
      - Converts to JPEG at 85% quality for size reduction
      - Passes through original JPEG bytes if no processing needed


==============================================================================
  5. REPORT GENERATION
==============================================================================

  --------------------------------------------------------------------------
  5.1  PptxWriter
  --------------------------------------------------------------------------

    PptxWriter (src/reporting/PptxWriter.h/.cpp) builds .pptx files from
    scratch using raw OOXML XML and a ZipWriter. It does not depend on any
    external PowerPoint library.

    Resource images used for branding (loaded from filesystem):
      - Cover_Page_Logo.jpg (cover slide background)
      - ccell_background.png (content slide background)
      - ccell_logo_full.png / ccell_logo_full_white.png

    Slide types:

      addCoverSlide(title, date):
        Full-background branded cover with title and date text

      addContentSlide(sheetTitle, table, plots):
        Data table on the left + plot images on the right
        Table supports custom column width fractions, header/alt-row colors

      addDualTableSlide(sheetTitle, topTable, bottomTable, plots):
        Two tables stacked vertically on the left + plots on the right

      addImageSlide(sheetTitle, images):
        Grid layout (up to 6 per slide, 2x3 arrangement)
        OR custom-positioned images with per-image x/y/w/h in inches

    Internal structure:
      - Each slide is stored as a Slide struct containing XML and a list
        of media pairs (zip-path, raw bytes)
      - Global media counter ensures unique filenames across slides
      - save() writes the complete OOXML skeleton: [Content_Types].xml,
        _rels/.rels, ppt/presentation.xml, slide masters, layouts, theme,
        and all slide XML + media files
      - Uses zlib for ZIP compression (LIBS += -lz)

    SlideImage struct: pngData bytes + position (x, y, w, h) in inches
    SlideTable struct: headers, rows, position, colors, optional column
      width fractions

  --------------------------------------------------------------------------
  5.2  TPM Reports (ReportGenerator)
  --------------------------------------------------------------------------

    ReportGenerator (src/reporting/ReportGenerator.h/.cpp) produces TPM
    reports from FileResult data:

      generateTestReport(FileResult, sheetName, ReportConfig):
        - Single-sheet report
        - Cover slide + content slide with data table and plots
        - Optional image slide if the sheet's samples have loaded images

      generateFullReport(FileResult, ReportConfig):
        - All-sheets report
        - Cover slide + one content slide per sheet + image slides
        - Progress callback for status bar updates

    ReportConfig controls:
      - includeTPM, includeEfficiency, includeBurnClogLeak, includeStdDev
      - includePlots, includeImages
      - singleSheetOnly + singleSheetName
      - selectedColumns (empty = all)
      - outputPath, reportTitle

    buildPlots() renders sheet data into PNG plot images.
    buildTable() constructs SlideTable from SheetResult metrics.
    collectImages() gathers per-sample images for image slides.

  --------------------------------------------------------------------------
  5.3  Sensory Reports
  --------------------------------------------------------------------------

    Generated directly by SensoryPanel (not ReportGenerator):

      generateSingleReport():
        - Cover slide with test title and date
        - Content slide: score table on left (columns: Sample + 5 metrics
          + Comments) + radar chart PNG on right
        - Optional image slide if the session has linked images (custom
          positioned or grid layout)

      generateFullReport():
        - Shows a session picker dialog (all sessions selected by default)
        - Calls generateCombinedPptx() (static method)
        - Cover slide for the overall report
        - If sessions span multiple test titles, inserts a sub-cover slide
          per group
        - One content slide per session (table + radar chart)
        - Image slides after each session's content slide if images exist
        - Cumulative/averaged summary slide at the end

      generateStats():
        - CSV statistics report (not PPTX)
        - Per-metric statistics: sample size, mean, std dev, std error,
          min, max, range, outliers (> 2 sigma), chi-square test
        - Raw data table with all scores and comments

  --------------------------------------------------------------------------
  5.4  Image Slides
  --------------------------------------------------------------------------

    Both TPM and sensory reports include image slides when images are
    available. Two layout modes:

      Custom-positioned: When imageLayouts are present (set via
        ImageViewDialog), images are placed at their exact inch positions
        using addImageSlide(title, QVector<SlideImage>).

      Auto-grid: When no custom layouts exist, images are arranged in a
        2x3 grid using addImageSlide(title, QVector<QByteArray>).

    Images are cropped and compressed via loadAndCropImage() before
    embedding in the PPTX.

  --------------------------------------------------------------------------
  6.10 Database Operations
  --------------------------------------------------------------------------

    DatabaseManager provides:
      - saveFile(FileResult): Replaces the entire file hierarchy in a
        single transaction (delete old + insert file/tests/samples/rows/
        images)
      - loadFile(int id) / loadFileByPath(path): Reconstructs a full
        FileResult from the database
      - listFiles() / removeFile(id): File listing and deletion
      - deduplicateFiles(keepPerName): Keeps only the N most recent entries
        per file_name, removes "unknown" template entries
      - recentFilePaths(): Last 20 file paths by loaded_at
      - saveSensorySession(): Tester-aware upsert (session_name +
        tester_name + date). Cleans up orphaned images before re-insert.
      - loadSensorySession() / loadSensorySessions(): Sensory session CRUD
      - listSensoryRecords() / removeSensorySession(): Listing and deletion
      - nextDefaultTestName(): Auto-generates "test_NNNN" names
      - setSetting() / getSetting(): Key-value settings store
      - Schema migration: ALTER TABLE adds tester_name if missing


==============================================================================
  7. SESSION MANAGEMENT
==============================================================================

  --------------------------------------------------------------------------
  7.1  TPM Mode
  --------------------------------------------------------------------------

    New File (onNewFile):
      - Locates the standardized test template Excel file
      - Runs Python (openpyxl) to list available test sheets
      - Shows NewFileDialog for user to select which tests to include
      - Copies template and removes unselected sheets via Python
      - Loads the new file

    Load File (onLoadFile):
      - File dialog for .xlsx/.xls files
      - Background loading via QFutureWatcher and QtConcurrent
      - ExcelReader parses the file; DataProcessor extracts samples
      - SheetProcessors handle different template versions
      - File appears in navigator tree; first sheet displayed

    Close File (onCloseFile):
      - Prompts to save to database if there are unsaved modifications
      - Removes the file from m_loadedFiles and clears associated
        cleanup exclusions
      - If no files remain, clears all UI

    Database Update (Ctrl+U):
      - Saves all modified TPM files to the SQLite database
      - Also saves all sensory sessions (if in sensory mode)
      - Tracks modifications via m_modifiedFilePaths set

  --------------------------------------------------------------------------
  7.2  Sensory Mode
  --------------------------------------------------------------------------

    New Session (ribbon button):
      - SensoryPanel::newSession() creates a blank session
      - One default sample card, all fields cleared

    Save (Ctrl+S or ribbon button):
      - Writes to .json, .xlsx, and database simultaneously
      - First save prompts for file location; subsequent saves reuse path
      - Auto-shows Save As dialog if session label doesn't match filename
      - Resolves test name (prompts to reuse previous or auto-generate)

    Load Files (ribbon button):
      - File dialog accepts .xlsx, .json, and all files
      - JSON files parsed as round-trip format from saveToJson()
      - Excel files auto-detected: saved format vs standardized template
      - Groups data by tester, creating one session per tester

    Load Database (ribbon button):
      - Tree-based picker showing all database sessions grouped by test
      - Supports multi-select and parent-node selection

    Close (ribbon button):
      - Closes selected sessions from the navigator (supports multi-select)
      - If all sessions are closed, leaves empty panels (no auto-create)

  --------------------------------------------------------------------------
  7.3  Database Browser
  --------------------------------------------------------------------------

    DatabaseBrowserDialog (src/ui/DatabaseBrowserDialog.h/.cpp) provides
    a two-tab interface:

      TPM Data tab:
        - Tree view of all stored files with expandable sheets/samples
        - Filter text field
        - Load, Load All, Delete, Cleanup (deduplication) buttons
        - Double-click or Load button returns selected file IDs

      Sensory Data tab:
        - Tree view of sensory sessions grouped by test title
        - Filter, Load, Delete buttons
        - Generate Report button (creates combined report from selection)

    Accessed via Tools > Database or by loading from the database browser
    in either mode.

  --------------------------------------------------------------------------
  7.4  Data Cleanup
  --------------------------------------------------------------------------

    DataCleanupDialog allows excluding specific data rows from TPM
    calculations, plots, and reports:
      - Exclusions stored as QMap<QString, QSet<int>> keyed by
        "fileIdx:sheetIdx:sampleIdx" with sets of excluded row indices
      - buildCleanedSample/Sheet/File create copies with excluded rows
        removed
      - Reset Cleanup button clears all exclusions for the current sheet
      - Cleanup state persists during the session but is not saved to
        the database

  8. BUILD CONFIGURATION
==============================================================================

  --------------------------------------------------------------------------
  8.1  DataViewerEnterprise.pro
  --------------------------------------------------------------------------

    Qt modules: core gui widgets sql concurrent network
    C++ standard: C++17
    Target: DataViewer (app)
    RC_ICONS: resources/images/ccell_icon.ico (embeds icon in .exe)

    NOTE: RESOURCES (.qrc) is disabled because Qt 6.10.1's rcc generates
    binary TSD format instead of compilable C++ source. Icons are loaded
    from the filesystem via resourcePath() instead of the Qt resource
    system.

  --------------------------------------------------------------------------
  8.2  Build Commands
  --------------------------------------------------------------------------

    # Step 1: qmake
    "C:/Qt/6.10.1/mingw_64/bin/qmake.exe" DataViewerEnterprise.pro \
      -spec win32-g++

    # Step 2: windres (manual, needed because windres calls gcc internally)
    "C:/Qt/Tools/mingw1310_64/bin/windres.exe" \
      "--preprocessor=C:/Qt/Tools/mingw1310_64/bin/gcc.exe" \
      "--preprocessor-arg=-E" "--preprocessor-arg=-xc-header" \
      "--preprocessor-arg=-DRC_INVOKED" \
      -i DataViewer_resource.rc \
      -o release/DataViewer_resource_res.o \
      --include-dir=. -DUNICODE -D_UNICODE -DWIN32

    # Step 3: make
    "C:/Qt/Tools/mingw1310_64/bin/mingw32-make.exe" -f Makefile.Release \
      CXX="C:/Qt/Tools/mingw1310_64/bin/g++.exe" \
      LINKER="C:/Qt/Tools/mingw1310_64/bin/g++.exe"

    # Step 4: Deploy Qt DLLs
    PATH="C:/Qt/Tools/mingw1310_64/bin:C:/Qt/6.10.1/mingw_64/bin:$PATH" \
    "C:/Qt/6.10.1/mingw_64/bin/windeployqt6.exe" \
      --release --no-translations release/DataViewer.exe

    # Step 5: Build installer
    "C:/Program Files (x86)/Inno Setup 6/ISCC.exe" installer.iss
    # Output: dist/DataViewer-setup.exe

    Full paths for CXX/LINKER are required because the MSYS bash shell
    doesn't inherit the Windows PATH for g++. The windres step must be
    run manually because windres calls gcc for preprocessing and gcc
    isn't in PATH either.

  8.3  External Dependencies
