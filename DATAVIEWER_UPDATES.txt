SESSION: 2026-03-17  (Before Weight + PPTX repair fixes)
--------------------------------------------------------------------------------
COMPLETED:
  [21] BEFORE WEIGHT ZEROS AFTER FIRST ROW (was BUG-A)
       ROOT CAUSE: The Excel template uses formulas for Before Weight in data
                   rows 2+: beforeWeight[i] = afterWeight[i-1]. When the file
                   is saved by openpyxl (via New File or Edit Headers), cached
                   formula values are stripped. The Python reader uses
                   data_only=True which reads cached values — so formula cells
                   return None/0. Excel displays correctly because it evaluates
                   formulas on open, but openpyxl cannot.
       FIX:    Added a repair pass in SheetProcessor::buildSampleResult() after
               the DataRow vector is built. For each row i>0, if beforeWeight
               is 0 and the previous row has a valid afterWeight, copy it
               forward: rows[i].beforeWeight = rows[i-1].afterWeight.
               This matches the known template formula pattern and works
               regardless of how the file was saved.
      FILES:   src/pipeline/SheetProcessors.cpp

  [22] PPTX REPAIR DIALOG ON EVERY REPORT (was BUG-B)
       ROOT CAUSE: buildSlideRelsXml() only emitted image relationships (rId1,
                   rId2, etc. for media). OOXML requires every slide to
                   reference a slideLayout in its .rels file. The missing
                   slideLayout relationship caused PowerPoint to trigger a
                   repair dialog on every open.
                   (The previous shape-ID collision fix [15] was also needed
                   but was not the sole cause.)
       FIX:    Added a slideLayout relationship after all image relationships
               in buildSlideRelsXml(). The layout rId is media.size()+1 to
               avoid collision with image rIds. Points to
               ../slideLayouts/slideLayout1.xml.
      FILES:   src/reporting/PptxWriter.cpp

  [23] PUFFS COLUMN ZEROS — formula cells not evaluated by openpyxl
       ROOT CAUSE: Same class of issue as [21]. The Puffs column in the template
                   uses formulas with variable increments (not constant 10-puff
                   steps). openpyxl data_only=True cannot evaluate formulas —
                   it only reads cached values, which are stripped when openpyxl
                   saves the file. Unlike Before Weight (which has a known
                   pattern: previous row's After Weight), Puffs increments vary
                   per row and cannot be reconstructed from other data.
       FIX:    Rewrote the Python reader script in ExcelReader.cpp to use
               win32com (COM automation) as the primary reader. This opens the
               file in a hidden Excel instance which evaluates ALL formulas
               correctly — puffs, before weight, and any other formula-based
               column. Falls back to the previous openpyxl data_only=True
               approach if win32com is not available (e.g. pywin32 not
               installed or Excel not present).
               COM reader reads from A1 to the end of UsedRange for consistent
               column indexing. Handles COM date objects (pywintypes.TimeType).
      FILES:   src/ExcelReader.cpp

  [46] NESTED SQLITE CURSOR BUG — DB-loaded files showed no sheets or data
       ROOT CAUSE: loadFile() had deeply nested QSqlQuery objects inside
                   while(outerQuery.next()) loops.  Qt's SQLite driver
                   invalidates the outer cursor when an inner query is
                   executed on the same connection, causing the outer loop
                   to silently terminate after the first iteration.
       FIX:    Rewrote loadFile() with "collect-first" pattern:
               Step 1 — query file metadata, copy to local vars, close query.
               Step 2 — collect all test IDs into QVector<TestInfo>, close.
               Step 3 — for each test, collect sample IDs into QVector, close.
               Step 4 — for each sample, load rows and images in separate
                         scoped queries (no nesting at this level).
               tpmTrend/puffCounts are rebuilt in C++ at the end of each
               sheet (they are computed vectors, not stored in the DB).
       FILES:  src/database/DatabaseManager.cpp

--------------------------------------------------------------------------------
OPTIMIZATION SUGGESTIONS
--------------------------------------------------------------------------------
  1. SheetProcessors factory: consider auto-registration pattern (static
     initialiser map) instead of the current switch/if chain — makes adding
     new sheet types easier without touching the dispatch code.

  2. PlotEngine marginate config: expose marginLeft/Right/Top/Bottom on
     PlotConfig so callers can tune report vs. GUI sizing independently.

  3. Notes aggregation: consider preserving puff-count context as
     "Puff 10: <note>; Puff 20: <note>" so readers know which measurement
     the note refers to; requires augmenting the notes joining in buildTable().

  4. PPTX table row height: currently hardcoded to 304800 EMU (~1/3").  Rows
     with long notes may overflow.  Consider computing row height from note
     length or switching to auto-fit (set tbl h attribute dynamically).

  5. Resource caching in PptxWriter: m_resourceCache is per-instance but the
     writer is re-created for every report.  Move cache to a singleton or
     pass it in if multi-sheet reports become slow.

  6. QXlsx performance: for large files (>5000 rows) the full-cell-read loop
     in ExcelReader may be slow.  Profile and consider row-streaming or lazy
     loading for non-visible sheets.

  7. Font embedding in PPTX: Montserrat is specified in cover/content slides
     but not embedded.  If the target machine doesn't have Montserrat installed
     PowerPoint will substitute.  Consider bundling the font bytes in resources
     and embedding via the font element in theme1.xml.
