### M1 — `loadFile` N+1 → bulk SELECTs

**File**: `src/database/DatabaseManager.cpp:509-740`. Currently `1 (file) + 1 (tests) + N_tests × (1 samples + N_samples × (1 data_rows + 1 images))` round trips — easily 100+ for a typical file with 5 sheets × 20 samples × 10 rows. Each round trip is a Postgres network hop plus driver overhead. File-switch latency dominates the UX as reported in the v2.0.1 handoff.

Replace with 4 bulk SELECTs filtered on `file_id` (or joined transitively), bucket in memory by parent id:

```sql
-- 1. tests for this file
SELECT id, version, sheet_name, template_version, overall_avg_tpm,
       overall_stddev_tpm, is_raw_table, sort_order
FROM tests WHERE file_id = $1 ORDER BY sort_order;

-- 2. all samples whose test is in this file
SELECT s.id, s.test_id, s.version, s.sort_order, s.sample_name, ...
FROM samples s JOIN tests t ON s.test_id = t.id
WHERE t.file_id = $1 ORDER BY s.test_id, s.sort_order;

-- 3. all data_rows whose sample is in this file
SELECT dr.id, dr.sample_id, dr.version, ...
FROM data_rows dr JOIN samples s ON dr.sample_id = s.id
                  JOIN tests t   ON s.test_id    = t.id
WHERE t.file_id = $1 ORDER BY dr.sample_id, dr.sort_order;

-- 4. all images whose sample is in this file
SELECT im.id, im.sample_id, im.version, im.file_name, im.image_data, ...
FROM images im JOIN samples s ON im.sample_id = s.id
               JOIN tests t   ON s.test_id    = t.id
WHERE t.file_id = $1 ORDER BY im.sample_id, im.sort_order;
```

Then in C++: build a `QHash<qint64, QVector<SampleRow>>` keyed by `test_id`, etc., and walk in-memory instead of issuing per-parent queries.

**Test** (`tests/tst_databasemanager`): `loadFile_singleQueryPerChildTable()`. Hook into `QSqlQuery` counts via a connection log — or, simpler, instrument `PostgresConnection` with a debug query-counter that the test can read, gated behind `#ifdef DVE_TEST`.

### H8 — ImageCache, session-scoped

**File**: `src/database/DatabaseManager.cpp` image-blob materialization (~lines 706-714 in `loadFile`, similar in `loadSensorySession`/`loadDetailedSensorySession` via `loadImagesFor`) and `src/MainWindow.cpp` close path.

## Critical repo quirks (read these before editing)

1. **MIP-encryption on source files at rest.** Microsoft Information Protection sensitivity labels re-encrypt `.cpp`/`.h` files when the OS touches them (including `git checkout` between branches). Bash `cat`/`grep`/`Read`/`Edit` see `%TSD-Header-###%` ciphertext. **Run `python tools/decrypt_via_copy.py --apply` from the worktree root before any C++ build attempt or Read.** Python interpreter is on the MIP allowlist and bypasses encryption. The script is idempotent and fast.

2. **Creating new source files via Python.** The `Write` tool's create-file path works but a freshly-written `.cpp`/`.h`/`.py` may get a MIP label as soon as it's closed. Pattern used in Phases 1 / 2 (write a helper `.py` then run it):
   ```python
   import os
   path = r"<absolute path>"
   content = r"""...file body..."""
   if os.path.exists(path): os.remove(path)
   with open(path, "w", encoding="utf-8", newline="\n") as f:
       f.write(content)
   ```
   For SQL / `.pro` / Markdown files this isn't necessary — MIP only targets code.

3. **Qt 6.10.1 + MinGW 13.1.0 + qmake** (not CMake). `-Werror -Wall -Wextra -Wpedantic` is enforced. **`VERSION` bumps in the .pro require `mingw32-make clean` + re-qmake before the next installer rebuild** (handled by `build_installer.bat` failing fast on a version mismatch).

4. **Three Postgres connections live concurrently**: `PostgresConnection::queryDb()` (main UI thread), `listenDb()` (NOTIFY listener thread), `LiveSyncWorker`'s dedicated `dve_livesync_worker_<uuid>` (its own QThread). Never share `QSqlQuery` instances across them.

5. **Bash CWD drift.** The Bash tool sometimes keeps a stale `cwd` between invocations. Prefix any command depending on it with `cd "<absolute worktree path>" && ...`. The absolute path is in the TL;DR above.

6. **qmake doesn't track header dep changes reliably.** After modifying a header that's `#include`d widely (e.g., `ReportData.h`), if `mingw32-make` says "Nothing to be done", re-run qmake to refresh dependencies:
   ```bash
   cd build
   /c/Qt/6.10.1/mingw_64/bin/qmake.exe -spec win32-g++ ../DataViewerEnterprise.pro CONFIG+=release
   mingw32-make -j8
   ```

7. **QtTest binary output doesn't reach pipe-captured stdout** on this MinGW build. Always use `-o file,txt` and `cat` the file:
   ```bash
   ./tests/tst_xxx/release/tst_xxx.exe <slot_name> -o /tmp/out.txt,txt
   cat /tmp/out.txt | tail -15
   ```

8. **`-Wunused-function` is enabled** (it's part of `-Wall`). If you delete the last caller of a helper, delete the helper too (or stub it as `[[maybe_unused]]`). This bit Phase 2's `insertImagesFor` — get ahead of it.

9. **Commit signing.** The git commits in Phases 1/2 emitted a "Committer identity warning" — benign, not blocking. The user has not asked you to set up `git config --global` here, so leave it alone.
