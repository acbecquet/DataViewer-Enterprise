# v2.10 Phase 1 - Multi-User Edit Integrity (DV-25 + DV-28) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A committed edit in a co-open sensory or detailed-sensory session can never be reverted by a stale whole-session save (DV-25), and an unchanged persisted session is never written at all (DV-28).

**Architecture:** Repro first (failing E2E scenarios against the test Postgres), then two independent layers: (1) extend the dirty-aware read-merge-write so ALL per-cell-committed sample fields are DB-authoritative-unless-locally-dirty, in both panels' merge functions; (2) a per-session `dirty` flag + pure `needsSave` helpers gating all four whole-session save loops. Producers (flag setters) land BEFORE the gate so nothing is ever skipped that has unsaved edits.

**Tech Stack:** C++17 / Qt 6.10, qmake + MinGW, Qt Test against the `dve-test-pg` Postgres 16 container.

**Master spec:** `docs/superpowers/specs/2026-07-16-v2.10-master-spec.md` (Phase 1 section). Read it first.

```cpp
bool sensorySessionNeedsSave(const SensorySession& s)
{
    if (s.id <= 0) return true;                        // never persisted
    if (s.dirty) return true;                          // any local edit this run
    if (!s.dirtyCells.isEmpty()) return true;          // per-cell edits recorded
    if (!s.removedSampleUids.isEmpty()) return true;   // pending removals
    if (!s.originalSessionName.isEmpty()
        && s.originalSessionName != s.sessionName)     // pending rename -> INSERT
        return true;
    return false;
}
```
