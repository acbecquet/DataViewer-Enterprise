## Learnings (project gotchas a fresh session MUST internalize)

- **Windows-only, Qt 6.10.1 qmake + MinGW 13.1.0, `-Werror -Wall -Wextra -Wpedantic`.** No CMake,
  no MSVC. `tests\run-tests.ps1` runs the 54-suite gate (needs Docker `dve-test-pg` for the DB
  suites; they skip cleanly if `DVE_TEST_PG_CONN` is unset). If Docker is off, ASK the owner to
  start it - do not start it yourself (`[[docker-ask-user-to-start]]`).
- **MIP encryption:** source files at rest may be MIP-ciphertext (`%TSD-Header-###%`). ALWAYS run
  `python tools/decrypt_via_copy.py --apply` before any C++ build. The Write/Edit tools produce
  PLAINTEXT at rest; Python-written files get MIP-LABELED (ciphertext) - so write `.md`/config via
  Write, and if you must write source via Python, decrypt right after (`[[mip-labels-python-writes]]`).
- **VERSION bump => clean rebuild.** qmake does not notice `VERSION` changes, so `main.o` (which
  embeds `-DDVE_APP_VERSION`) goes stale. After bumping: `qmake CONFIG+=release && mingw32-make
  clean && mingw32-make -j8`. `build_installer.bat` has a version-match gate that will reject a
  stale exe.
- **`make` has NO per-object rule.** `mingw32-make release/Foo.o` fails with "No rule". Use the full
  `mingw32-make -j8` (it recompiles changed TUs + relinks). Cost me two wasted cycles this sprint.
- **Build the installer from bash:** `MSYS_NO_PATHCONV=1 cmd /c '.\build_installer.bat' < /dev/null`
  (the `.\` and redirect matter). It packages the ROOT `release\` tree, not `build\release\` -
  rebuild in-tree first (`[[build-installer-from-bash-dotslash]]`). `release\python_bundle.zip`
  already exists (2026-06-17) and can be reused; `tools\prepare_python_embed.bat` is only needed if
  it's missing.
- **NEVER touch Synology** (`%USERPROFILE%\SynologyDrive\...`) - not even a read/`ls`. The owner is
  the human prod gate and does every installer/NAS drop by hand.
- **NEVER kill Excel processes** - the owner runs Excel live for testing (`[[never-kill-excel-processes]]`).
- **Versioning:** v2.9 internal test builds are stamped **v2.8.1 .. v2.8.x**; only the FINAL deployable
  build becomes **v2.9.0**. Never stamp an internal build with the target minor.
- **Owner working style:** token-efficient (no big agent fan-outs; verify inline; cap any workflow
  ~10-15 agents - `[[feedback-token-efficiency]]`); wants generous self-runnable CLOSED-LOOP harnesses
  for anything hard to eyeball (`[[prefer-closed-loop-harnesses]]`); pixel-perfection standard on any
  UI; keep the sprint tracker updated but COMMIT it only when asked.
- **Phased cadence that worked this sprint:** master spec is the north star; write a per-phase plan;
  implement inline (subagents only for standalone/parallel tasks); gate = full suite green + `-Werror`
  clean + a visual/pixel probe; bump internal version + build installer; owner smoke test; iterate;
  wrap to the deployable minor on sign-off. Update the master spec Phase Log after every phase.
