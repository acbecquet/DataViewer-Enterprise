## Learnings

- **A green closed-loop harness is NOT the same as good UX.** `--ui-stress` only checks "content clipped without a scrollbar." The owner watched the live resize and caught both docks fully HIDING at <760 (Task 11), which made their buttons unreachable - a real problem the clip-metric literally counted as the feature working (`nav_visible:false`). Always eyeball the PNGs; do not over-claim "UI is correct" from a passing metric. This directly overturned my premature "no real clips, UI renders correctly" conclusion.
- **The `--ui-stress` 28/28 initial failures were ALL harness measurement artifacts, zero real clips.** Root causes were in the harness, not the UI: it mispaired `need` (from `regionWidget()` - often a different or hidden widget) against `vp`/`scrollbar` (from `scrollHostFor()`), and vertical-checked the horizontal-only ribbon ScrollHost. Fix = single-ScrollHost pairing + per-axis checks.
- **AppTheme hardcodes `font-size` in its QSS stylesheet, and a QSS `font-size` overrides `QApplication::setFont()`.** So simulating text-scaling by setting the app font was a genuine no-op (x2.0 PNG was pixel-identical to x1.0). The harness now rewrites the QSS font-size rules per scale. Open question worth a later look: whether the hardcoded QSS font-size limits the app's response to the Windows "text size" accessibility slider (it does scale with display DPI via points).
- **Qt Tests must stay LIGHT - never instantiate `MainWindow` in a headless Qt Test.** Its ctor opens a Postgres/offline-snapshot DB connection and spawns Python; it is flaky/hangs headless. The full-window no-clip guarantee is verified by `--ui-stress` running in-process inside the real `DataViewer.exe`, not a Qt Test. Do not reintroduce an `app_sources.pri`/MainWindow-in-test approach.
- **`QT_QPA_PLATFORM=offscreen` has NO fonts on this Qt 6.10 MinGW build** (`QFontDatabase: Cannot find font directory`), so all `QFontMetrics` return 0 and font/layout tests + `--ui-stress` (which grab()s real text) MUST run on the NATIVE `windows` platform, exactly as `tests/run-tests.ps1` does. Never run `--ui-stress` offscreen.
- **The long-standing flaky `tst_responsivelayout` multi-slot segfault** was a dangling `m_window` (raw `QWidget*` dereferenced in `stopTracking()` after the tracked widget was destroyed; `0xfeeefeee` poison). Fixed at the source with `QPointer<QWidget>`, which also closed a latent production dangle at MainWindow shutdown. Chip `task_a8131d10` is resolved (could not dismiss it - predates an app restart).
- **MIP:** src `.cpp/.h` are ciphertext at rest. Write NEW source via Python delete-then-rewrite (not the Write/Edit tools), edit EXISTING source with the Edit tool, and `python tools/decrypt_via_copy.py --apply` before EVERY build. `.pro`/`.md`/`.html` are not labeled.
- **Build from Bash:** `MSYS_NO_PATHCONV=1 cmd /c "set PATH=C:\Qt\Tools\mingw1310_64\bin;C:\Qt\6.10.1\mingw_64\bin;%PATH% && ... " < /dev/null`. Single-slash `/c`, and `.\build_installer.bat` / `.\release\DataViewer.exe` (cmd here does not search CWD for bare names). The `//c` form silently runs nothing.
- **Version convention:** internal work increments the patch (`z`); the deployable minor (`y`) bump happens only at the owner-approved release. This work is v2.6.1 internal -> v2.7.0 deploy.
- Subagent implementers repeatedly did the right thing by STOPPING and escalating rather than fudging (a test-helper ceiling-rounding line-count bug; a missed clip site; the real segfault root cause vs the plan's insufficient fix). Trust that pattern and verify their claims (build output, git blobs, and for UI, the PNGs).
