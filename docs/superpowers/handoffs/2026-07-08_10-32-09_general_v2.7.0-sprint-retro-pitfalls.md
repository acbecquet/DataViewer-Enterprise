## Learnings (READ THIS - the pitfalls to avoid in v2.8)

### 1. The installer packages the ROOT `release/` tree, NOT `build/release/`

`installer.iss` sources `release\DataViewer.exe`.
A rebuild in the out-of-tree `build/` dir does NOT update it.
This shipped the draw-pressure fix as a **no-op installer** - the owner installed it and correctly reported "did not fix at all."
The FileVersion gate could not catch it because the version string was unchanged.

- For installer builds, always rebuild IN-TREE: `qmake -spec win32-g++ CONFIG+=release DataViewerEnterprise.pro && mingw32-make -f Makefile.Release -j8` at the repo root.
- The root Makefile can be stale (a newly-added `.cpp` yields undefined-reference link errors); re-run qmake at root to regenerate it.
- Verify the artifact chain by TIMESTAMPS (src < release exe < dist installer), and symbol-verify the fix is in the packaged object (`nm release/Foo.o | grep symbol`).
- `build_installer.bat` now has a staleness gate (`9f3ab97`) that refuses to package an exe older than any `src/` file. Do not remove it.

### 2. "Now shows 0 / wrong" data bugs - inspect the REAL file first

Viscosity reading 0 was NOT a code regression.
The tester typed `800kcp` (units) into numeric cell B3, and `QVariant::toDouble` returns 0 for that.
I read the actual workbook via openpyxl (read-only) and saw the text before touching any code.
Header cells now parse tolerantly via `ExcelReader::tolerantCellDouble`.
Always reproduce against the real artifact before hunting the parser.

### 3. A single shared flag must be derived from the max/union over ALL views

Ribbon compaction is one global flag but the decision measured only the current tab's width.
So Home compacted while Reports/Tools/Settings kept labels, and switching tabs flipped the toolbar.
The fix measures the widest tab.
This is a recurring shape - watch for it wherever one boolean drives N surfaces.

### 4. Item-view wrapping via viewport-width-dependent sizeHints FROZE the app

A wrapping delegate for the navigator lists/trees, plus Adjust-mode relayout, plus live NOTIFY churn, formed a relayout feedback loop that hard-froze the UI within seconds.
It was reverted (`3e001d6`).
For long text in lists/trees use SCROLL-to-end (ElideNone + content-sized column + ScrollPerPixel) plus tooltips, NOT wrapped size hints.
Wrapping is only safe in a QTableWidget (ResizeToContents rows) and a QLabel.
See the `no-cut-off-text-ever` memory.

### 5. Office COM automation must use `DispatchEx`, never `Dispatch`

`win32com.client.Dispatch("Excel.Application")` ATTACHES to the user's already-running Excel, and a later `.Quit()` closes THEIR live session.
This repeatedly killed the owner's active test sessions and was a serious workflow-damage complaint.
`DispatchEx` creates a private, invisible instance; Quit only that instance, in a try/finally.
This is now the rule (`41e3de2`, plus the `never-kill-excel-processes` memory).

### 6. Standing axis rules for EVERY x-y plot (owner directive, now codified)

X runs 0..(last data point + 1); y is anchored at 0 and tops out at (data max + 1). Always.
The per-chart floors (`computeTpmYMax` 7/25, `drawPressureYMax` 2) were removed.
A `PlotConfig` with `autoScale=false` must set BOTH axes - the draw-pressure x-axis was stuck at the struct default 0..1 because only y was set.
Do not reintroduce special-case scaling without an explicit owner ask.

### 7. Release-merge divergence

The sprint branch was cut from the v2.6.0 wrap commit, so `main` diverged during the sprint (sidecar v1.3 merge, Mfused form commits, a v2.6.0 installer hotfix).
A fast-forward was impossible.
Before tagging a release: run `git log HEAD..main` to see what diverged, merge main INTO the branch, and verify the incoming diff touches no app code (`git diff --stat MERGE_BASE main`) before moving main.
`git fetch . <branch>:main` fast-forwards main WITHOUT a checkout, which is useful when an untracked file blocks `git checkout main`.

### 8. Every "load/open" bug has multiple entry points

The entry points are TPM vs sensory vs detailed, each crossed with file-open / multi-file / DB-browser / recovery.
The v2.4.x dedup saga wasted four round-trips patching the wrong path.
When the owner describes a load behavior, check ALL entry points.
See the `cover-every-load-path` memory.

### 9. Build-from-Bash and MIP mechanics

Installer build from Git Bash: `MSYS_NO_PATHCONV=1 cmd /c '.\build_installer.bat' < /dev/null` - the `.\` is required, a bare name is "not recognized."
Before any C++ build run `python tools/decrypt_via_copy.py --apply` (MIP re-encrypts source at rest).
The decrypt step returns non-zero on one self-relabeling test `.py`, which is non-fatal - chain it with `|| echo`.
See the `build-installer-from-bash-dotslash` and `mip-labels-python-writes` memories.

### 10. Closed-loop probes earned their keep

Standalone Qt apps that render a widget or plot to PNG caught what scrollbar-range metrics and version strings could not.
One gotcha: a `QToolButton` in `ToolButtonIconOnly` mode with a NULL icon falls back to elided text, so give probe buttons a real icon or assert `toolButtonStyle()==0`.
The owner values pixel-level verification; keep building these harnesses (memory `prefer-closed-loop-harnesses`).

### 11. Sprint-tracker `lastUpdated` bloat

It kept accumulating nested `[Earlier: ...]` history and unbalanced brackets.
Keep it to ONE honest line and push detail into the task rows and commits.
Validate brace/bracket balance in the `DATA` object after every edit.
