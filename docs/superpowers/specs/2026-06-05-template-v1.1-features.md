# Automated Testing Template v1.1 — Design Spec

**Date:** 2026-06-05
**Branch / worktree:** `feature/excel-sidecar-v1.1` (off `main` @ `ad5887c`)
**Subsystem:** `excel-sidecar/` (the operator data-collection workbook + its build/gate pipeline)
**Output artifact:** `Automated Testing Template v1.1.xlsm` (built on the work machine via `build_clean_template.py --out "...v1.1.xlsm"`)

---

## Goal

Three operator-requested behaviors, shipped as **v1.1** of the Automated Testing Template, built through the existing clean-rebuild pipeline:

1. **Robust test-sheet recognition** for Add/Remove Sample — works on every checkbox test sheet **except** `Temperature Cycling Test #1` and `Test SOP's`.
2. **Specify Test Name** button (replaces the now-deprecated **Dry-Run Checklist**) — temporarily renames the workbook on disk to `<project> - <original>.xlsm` so techs can tell parallel-project copies apart at a glance, then auto-reverts on Upload All.
3. **Automatic Clog column** — derived from each block's Draw Pressure with color highlighting, on every test sheet.

**Non-negotiables:** repo stays the single source of truth (all three headless gates + docs updated to match); the build never authors data sheets except through the documented step added here; the source `.xlsm` and Synology are never touched from the dev machine.

---

## Background — what the recon established

**Data-sheet layout (the load-bearing fact).** Every standard test sheet is composed of repeating **12-column "sample blocks,"** with the column header on **row 4** and data from **row 5 down (through row 115 = `BLOCK_ROWS`)**. Within each block (block *b* starts at column `b*12 + 1`):

| Block col # (1-based) | Offset from block start | Block-1 col | Header (row 4) |
|---|---|---|---|
| 1 | +0 | A | `puffs` |
| 4 | +3 | D | `Draw Pressure (kpa)` |
| 7 | +6 | G | `Clog` |

So for a block starting at absolute column `s`, Draw Pressure is at `s+3` and Clog at `s+6` (block-1: D and G; block-2: P and S; …). Block count = number of contiguous block-start columns (1, 13, 25, …) whose row-4 cell reads `puffs`. Confirmed counts: Lifetime 2, Custom/User/Long/Rapid/Intense/Big-Headspace 4, Temp-Cycling-#2 6, Various-Oil 8, Negative-Pressure 12, Viscosity 16.

**The two exceptions are structurally distinct**, not just "named differently":
- `Temperature Cycling Test #1` — a step-completion checklist (`A4` is empty; "Step 1.1 / Complete?" rows; only `# Clog?` summary cells). No `puffs` blocks.
- `Test SOP's` — a prose SOP table (`A4 = 'Viscosity Compatibility Test'`). No `puffs` blocks.

**Root cause of "many tests not recognized" (Feature 1).** Detection today is `TestingTools.IsAllowedSheet`, an exact-match against a hardcoded pipe-delimited `ALLOWED_SHEETS` string. On the **current** template that string already lists the right 11 sheets and excludes #1 + SOP's — and `Custom Test Template` / `Temperature Cycling Test #2` (the two the operator reported failing) are both **present with clean geometry and exact names**. Therefore the failures are on **older project copies** (the parallel-project spilloff files) whose macros predate the v1.0 rebuild and carry a stale/shorter list. A name list is the wrong mechanism: it breaks silently across template versions and copies, and it has already drifted from the parallel list in the code (`ALLOWED_SHEETS` has 11 entries; `DataViewerUpload.CanonicalDataSheets` has 12). **Structural detection removes the whole failure class.**

**Build pipeline boundary (affects Feature 3).** `build_clean_template.py` authors only `_Settings`, `Test Selection`, the ribbon, and the VBA. It stamps each canonical data sheet blank from its veryHidden `_Template_NN` snapshot (`d.Cells.Clear()` + `t.UsedRange.Copy`). It does **not** write headers, columns, formulas, or conditional formatting onto data sheets today. Per-block formatting at sample-add time comes from `_Template_Master` (copied by `TestingTools.AddSample`, `BLOCK_COLS=12`, `BLOCK_ROWS=115`). So Feature 3 must be applied as a **new build step** that writes onto the data sheets + their snapshots + the master, not as a side effect of the existing stamp.

## Feature 1 — Structural test-sheet detection

**Decision:** replace the hardcoded name whitelist with structure-based detection on the same `puffs` marker the puff-picker already uses (`TestingTools.TryPuffStepPicker`, line 159).

**Changes — `excel-sidecar/TestingTools.bas`:**
- **Delete** `Private Const ALLOWED_SHEETS`.
- **Rewrite `IsAllowedSheet(ws)`** to: return `False` for `- Review` archive copies (suffix match), else `True` iff `LCase$(Trim$(CStr(ws.Cells(4, 1).Value))) = "puffs"`. `On Error Resume Next` guarded.
- **Harden `CountBlocks(ws)`** to count contiguous block-starts (cols 1, 13, 25, …) whose row-4 reads `puffs`, stopping at the first that doesn't — instead of `Cells(4, last).End(xlToLeft)`. Immune to stray cells beyond the last block; uses the identical signal as detection.

`AddSample`, `RemoveSample`, `ResetEquations` are unchanged otherwise — they already gate on `IsAllowedSheet` and size on `CountBlocks`.

**Why this satisfies the goal:** all 11 block-layout sheets (incl. the two reported failing) pass; `Temperature Cycling Test #1` and `Test SOP's` fail the `puffs` test and are excluded; `- Review` copies stay excluded (matching today's behavior, which excluded them only by name); future test sheets are covered automatically; nothing to hand-maintain or drift.

**Operator note (documented, not code):** existing parallel-project copies should be re-made from `v1.1` to pick up the robust detection.

## Feature 2 — Specify Test Name (replaces Dry-Run Checklist)

### Remove the Dry-Run Checklist feature (complete surface)
- **`customUI14.xml`** — delete the `btnDryRun` `<button>` element (in `boxDvActions`, 2nd position).
- **`DataViewerUpload.bas`** — delete `Public Sub Ribbon_DryRun(...)` and `Public Sub Btn_DryRunChecklist()`. **Keep** `RunChecklist`, `WriteFailures`, `ShowFailures`, `ValidateSheet`, `ValidateSamplePuffs` — Upload All shares them.
- **`check_sources.py`** — remove `Ribbon_DryRun` from the wrapper list, remove the `btnDryRun` element checks, remove the `Btn_DryRunChecklist` MsgBox check.
- **Docs** — `README.md`, `RUNBOOK-migrate-existing-template.md`, and `DataViewerUpload.InstructionsText` lose their Dry-Run mentions.
- **Leave alone:** `install_sidecar.py`'s `--dry-run`/`--apply` CLI flag is an unrelated installer-safety pattern, not this feature.

### Add the Specify Test Name feature
**New persisted state:** named range `DV_OrigFileName` → `_Settings!$B$7`, label "Original file name" in `A7`. Stores the workbook's canonical base name (no extension), captured **once** on first use.

**Ribbon — `customUI14.xml`:** new `btnSpecifyName` (label "Specify Test Name") in `boxDvActions`, 2nd position (where Dry-Run was), `onAction="Ribbon_SpecifyName"`.

**VBA — `DataViewerUpload.bas`:**
- `Ribbon_SpecifyName(control As IRibbonControl)` → `Btn_SpecifyName`.
- `Btn_SpecifyName`:
  1. If `DV_OrigFileName` is empty, set it to the current workbook base name (current name *is* the original on first use).
  2. `Application.InputBox` for a project/test name (`Type:=2`); Cancel → exit; **blank → revert to original**.
  3. Sanitize illegal filename characters (reuse the same check `Btn_UploadAll` already applies — extract into a shared `SanitizeFileName`/`HasIllegalFileNameChars`).
  4. Target = `<project> - <DV_OrigFileName>.xlsm` (or `<DV_OrigFileName>.xlsm` when reverting), in `ThisWorkbook.Path`.
  5. `RenameWorkbookTo(target)`.
- `RenameWorkbookTo(newFullPath)` helper: `ThisWorkbook.SaveAs Filename:=newFullPath, FileFormat:=52` (**xlsm — preserves macros**), then `Kill` the old path (clean rename — chosen option). All under `DisplayAlerts=False` with error handling; no-op if the path is unchanged.

Because the original is stored separately, re-running with a new project produces `<new> - <orig>` (no stacking), and blank input restores `<orig>`.

**Upload All revert hook — `DataViewerUpload.Btn_UploadAll`:** at the very top (before `PromptForFileName`, before any `Save`/`CopyFile`), call `RevertToOriginalName` — if `DV_OrigFileName` is set and the on-disk name differs, `RenameWorkbookTo(<orig>.xlsm)`. This guarantees the upload copies and `MakeTempXlsx` open the canonical path, and the file ends under its original name. No-op when the feature was never used.

**Scope decision (locked):** the project prefix affects the **on-disk workbook name only**. `DV_FileName` and the Upload All file-name prompt are untouched — uploaded data never carries the project prefix.

**Gates:** `check_sources.py` gains `Ribbon_SpecifyName` in the wrapper list + `btnSpecifyName` element checks + `Btn_SpecifyName` defined + assertions that `btnDryRun`/`Btn_DryRunChecklist` are gone. `verify_sidecar.py` `DEST` gains `DV_OrigFileName → _Settings`. `test_build_helpers.py` gains a `DV_OrigFileName` / 7-label assertion.

## Feature 3 — Automatic Clog from Draw Pressure

**Decision (locked):** Clog becomes an automatic formula + conditional-format color; operators no longer type it.

**Per-block rule.** For each block, the Clog column (`start+6`) keys off the Draw Pressure column (`start+3`), rows 5–115:

```
=IF(<Draw>="","",IF(<Draw>>=15,"Heavy Clog",IF(<Draw>>5,"Light Clog","")))
```

Partition (locked): blank or ≤5 → empty · `>5` and `<15` → `Light Clog` · `≥15` → `Heavy Clog`.

**Conditional formatting** — two rules per sheet, applied to the **union of that sheet's Clog columns** (rows 5–115) to avoid rule bloat:
- contains `Light Clog` → fill **#FFFF00** (yellow), font **#000000 black, bold**.
- contains `Heavy Clog` → fill **#C00000** (dark red), font **#FFFFFF white, bold** (readable on the dark fill).

**Where it's applied — new build step in `build_clean_template.py`,** run **after** the snapshot-stamp loop. Iterate every worksheet; for any whose block-starts read `puffs`, apply the Clog formula + the two CF rules to each block. This single pass uniformly covers:
- the live canonical data sheets,
- the veryHidden `_Template_NN` snapshots (so reset/rebuild keeps it; `_Template_11` = #1 mirror and `Test SOP's` are skipped automatically — no `puffs`),
- `_Template_Master` (so `AddSample`'s pasted blocks inherit it).

**Reset-Formulas consistency — `TestingTools.bas`:** add the Clog column (relative col 7, rows 5–115) to the `ResetEquations` `specs` array so Reset restores the Clog formula from `_Template_Master`. Update its confirmation MsgBox text to drop `clog` from the "will NOT be touched" data list (Clog is now a restored formula, not entered data).

**Gates:**
- `check_sources.py` (headless): assert `ResetEquations` specs include relative col 7; assert the reset MsgBox no longer lists `clog` as untouched data.
- `verify_sidecar.py` (work machine, against the built file): open a representative built sheet and assert the Clog cells hold the formula and the two CF rules exist. This is the cross-check that the build step actually wrote the formatting (headless gates can't see Excel CF).

## Build & acceptance (work machine)

1. `python excel-sidecar/build_clean_template.py --source "<live template>" --out "<...>\Automated Testing Template v1.1.xlsm"`
2. `python excel-sidecar/verify_sidecar.py --file "<...v1.1.xlsm>"` → VBA/ribbon match + Clog formula/CF present.
3. `python excel-sidecar/check_sources.py` and `python excel-sidecar/test_build_helpers.py --source "<...>"` → ALL PASS.
4. Operator acceptance (from `RUNBOOK`): Add/Remove Sample works on every checkbox sheet except #1 + SOP's; native checkboxes survive; Specify Test Name renames + reverts on Upload All (one file at a time); entering Draw Pressure fills Clog with the right text+color; uploaded `.xlsx` carries the personal name (no project prefix) and shows the Clog text.

Per project rules, the build, `verify_sidecar`, and acceptance run on the work machine; the dev machine ships only the repo changes. The installer/Synology drop is the user's manual step.

---

## Out of scope
- No change to the DataViewer C++ app. The uploaded `.xlsx` will show `Light Clog`/`Heavy Clog` text (cached formula values) in the Clog column instead of Y/N; **acceptance confirms DataViewer renders this acceptably** — but no C++ change is planned here.
- No cell-protection on the Clog column (a stray manual entry would overwrite the formula; Reset Formulas restores it).
- No change to the upload destinations, checklist logic, or the auto-update path.

## Risks & mitigations
- **Macro loss on rename** — `SaveAs FileFormat:=52` (xlsm) is mandatory; covered by an acceptance check (macros still run after rename).
- **`Kill` on a locked/old path** — guarded with error handling; failure surfaces a MsgBox and leaves both files (degrades to "keep both," never data loss).
- **CF rule bloat** — mitigated by one rule-pair per sheet over the union of Clog columns.
- **Source/repo drift** — every behavior above has a headless or built-file gate; `verify_sidecar` is the backstop that the built `.xlsm` matches the repo.
