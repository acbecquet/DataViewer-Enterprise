# Post-v2.0.7 Refactor Backlog

**Status:** Backlog — not scheduled
**Created:** 2026-05-20 (end of v2.0.7 cleanup)
**Source:** `docs/audits/2026-05-20-cleanup-audit.md`

Items the v2.0.7 cleanup audit identified but explicitly deferred. Each entry is a candidate for a focused standalone release. None of these are urgent — the v2.0.6 baseline runs correctly today.

## Why these were deferred

v2.0.7 was scoped as a "cleanup release with zero user-visible changes." The refactors below all touch hot code paths in big files; bundling them into a release that's labelled as cleanup would either:

1. Inflate the v2.0.7 blast radius and put correctness at risk, or
2. Force a v2.0.7 → v2.0.8 cascade where v2.0.7 ships, then a follow-up release ships these refactors anyway.

Better to ship each as its own focused PR with its own test gate. The deferrals below are independent — they can ship in any order.

## Out of scope here

- New features

## Process

When picking up any item:

1. Cut a focused branch off `main`: `git checkout -b refactor/<R-NNN-short-name>`.
2. Use the audit doc (`docs/audits/2026-05-20-cleanup-audit.md`) for context.
3. Per-finding commits where possible; one PR per item.
4. Required gates: clean `-Werror` build, 34/34 tests, `--self-test` green.
5. Frontend smoke from the user before merging to `main`.

Each item is independent; pick whichever has highest value-to-risk at the time. **Lowest hanging fruit:** R-005 (OfflineSnapshot split — clean boundaries), R-006 (PptxWriter split — no UI coupling), R-008 (empty stubs — pure deletion), R-013 (uniqueFilename inline).
